# 스마트폰 테스트용 빌드 (phone flavor)

Pleos 공모전용 원본은 **car** 빌드이며 기본값이다. car 빌드는 manifest·리소스가 기존 APK와 동일하다.

**phone** 빌드는 같은 코드에 `app/src/phone`의 manifest·리소스만 덮어쓴다. main 코드는 바꾸지 않는다.

## 호환성 점검 결과

| 항목 | 원본(car) | 폰에서의 영향 | phone 빌드 처리 |
|---|---|---|---|
| `uses-feature android.hardware.type.automotive required=true` | 차량 전용 선언 | 스토어 필터 대상이며 설치 경로에 따라 거부될 수 있음 | `required=false`로 덮어씀 |
| `uses-library android.car required=false` | 주행 제한 API | 폰에 없어도 설치됨 | 그대로 |
| `CarRestrictionMonitor` (android.car API) | 주행 제한 감시 | 기기에 FEATURE_AUTOMOTIVE가 없으면 연결하지 않고 '제한 없음'으로 동작함 | 동작은 같다. 모든 화면 위에 "차량 기능 미지원 · 검증 아님" 띠를 표시 |
| `distractionOptimized` 메타데이터 | 주행 중 허용 화면 | 폰에서는 무시됨 | 그대로 |
| `minSdk 28` / `targetSdk 34` | Android 9 이상 | 대부분의 폰 설치 가능 | 그대로 |
| `RECORD_AUDIO`, `<queries>` (LAUNCHER/HOME/RecognitionService) | | 폰에서도 동일하게 동작 | 그대로 (`QUERY_ALL_PACKAGES` 없음) |
| 기기 내 음성 인식 | API 31+ | 폰 기종에 따라 있음/없음 | 없으면 시스템 인식 동의 화면 (차량과 동일 정책) |
| 화면 배치 | 가로 차량 디스플레이 기준 | 세로 폰에서는 버튼이 잘림 | **세로 고정.** `src/phone/res/layout`의 세로용 레이아웃(메인, 즐겨찾기 행, 앱 선택 행, 호출어 등록, 음성비서)이 main을 덮어쓴다. 버튼은 두 줄 또는 세로로 쌓고, 등록·음성비서·플로팅 설정은 세로 스크롤 |
| Pleos SDK (Vehicle/NaviHelper) | 아직 미사용 (주석 처리) | 영향 없음 | — |

## 메인 화면 (phone 빌드, 일반 사용자용 음성비서 화면)

- 위에서부터: 로고·설정 아이콘, 소개 문구, 마이크와 호출어 이름, **실제 듣기 상태**, [직접 음성비서 실행], 안내 줄, '이렇게 말해보세요' 예시.
  - 예시는 동작하는 명령만 넣었다: 카카오톡 열어줘, 유튜브 열어줘, 최근 메시지 읽어줘.
  - 답장 예시는 실기기 확인 뒤 추가한다.
- 듣기가 꺼져 있거나 마이크 권한이 없으면 [호출어 듣기 켜기]가 나온다. 호출어가 없으면 [호출어 등록]이 나온다.
- 백그라운드 호출이 꺼져 있으면 "이 화면이 열려 있을 때만 들어요" 안내가 나온다. 누르면 설정으로 간다.
- 노란 개발용 띠는 메인 화면에서 빼고 아래쪽 작은 문구로 바꿨다. 다른 화면에는 그대로 있다.
- **[설정]** (`PhoneSettingsActivity`)
  - 호출어 듣기 켜기·끄기, 백그라운드 호출
  - 호출어: 재등록, 삭제
  - 권한: 마이크, 알림 접근, 앱 정보
  - 메인 화면에 내 앱 표시 (켜고 끄기)
  - 개발용 측정 (debug만)

## 호출어 감지 (phone 빌드)

- **문제 (갤럭시 실기기, 2026-11-08):** 화면에는 듣는 중으로 나오지만 불러도 반응하지 않았다.
  - 로그에 `segment 3100ms score≈0.42 threshold=0.202`가 1.5초마다 반복됐다. 조용한 방에서 25초 동안 확인했다.
  - 원인: 마이크 시작 직후 무음 프레임으로 소음 기준이 아주 낮게 잡힌다. 그러면 -55 dB를 넘는 실내 소음이 계속 '발화'로 판단된다.
  - 발화 중에는 소음 기준을 갱신하지 않으므로 구간이 끝나지 않는다. 호출어가 3초 덩어리에 섞여 따로 평가되지 못한다.
  - PC 재현(`gradlew --offline :wakeword-eval:run --args="startup"`, TTS 데이터): 무음 시작에 -52·-45 dB 소음이면 구간 43~44개가 모두 최대 길이로 잘렸다.
- **수정:** 폰 전용 모듈 `wakeword-phone`의 `AdaptiveWakeWordDetector`.
  - 무음 프레임은 소음 기준에서 뺀다.
  - 3초 넘게 쉬지 않는 '발화'면 소음 기준을 그 구간의 최저 레벨로 올린다.
  - 점수 계산과 개인 기준값(threshold)은 그대로다. 재현 결과 최대 길이 구간은 0개였다.
- **차량용:** `wakeword-core`는 차량용 APK와 공유하므로 바꾸지 않았다. 차량용에 반영하려면 별도 승인이 필요하다.
- 폰 빌드는 MyCarHub 화면에서도 이 감지기로 듣는다 (`PhoneMainScreen`, 로그 태그 `WakeWordForeground`). 백그라운드는 태그 `WakeWordBackground`.
  - main 코드의 자체 듣기(`wake_word.listen_enabled`)는 앱 시작 때 끈다. 사용자가 고른 켜기·끄기는 `phone_voice.listen_enabled`에 저장한다.
- 감지하면 짧은 알림음을 내고 음성비서 화면을 연다. 화면에는 "'뿡뿡이' 호출을 들었어요"가 표시된다.
- 진단 로그: `adb logcat -s WakeWordForeground WakeWordBackground`
  - `level avg/min/noise`: 2초마다
  - `segment ... score`: 발화 구간마다
  - `wake word detected`: 감지했을 때
- **즐겨찾기(내 앱):** 기능과 데이터는 그대로 두고 메인 화면에서만 숨겼다. 설정의 '메인 화면에 내 앱 표시'를 켜면 예전처럼 추가·실행·편집할 수 있다.
- **구현 방식:** main 코드와 차량용 화면은 바꾸지 않았다.
  - 폰 레이아웃이 MainActivity가 찾는 id를 모두 유지한다.
  - 옮긴 버튼은 숨긴 묶음 안에 둔다.
  - `PhoneMainScreen`(ActivityLifecycleCallbacks)이 폰 전용 뷰를 채운다.

## phone 빌드에서 테스트할 수 있는 것

- 즐겨찾기 앱 등록·실행·별칭
- 호출어 등록(5회 녹음, 품질 검사, 학습), 호출어 감지, 삭제·재등록
- 음성 명령: STT → 해석 → 앱 실행 (카카오톡 등 폰에 설치된 실제 앱)
- 마이크 권한 허용·거절·영구 거절 흐름
- 개발용 측정 화면 (debug 빌드)

## 메시지 읽기·답장 (phone 빌드만)

1. 메인 화면 음성 호출 카드의 **"메시지 읽기·답장: 알림 접근 필요 (눌러서 설정)"**을 누른다.
2. 안내를 확인하고 [설정 열기]를 누른 뒤 **MyCarHub 폰테스트**를 켠다.
   - 앱은 MyCarHub 전용 상세 화면(`ACTION_NOTIFICATION_LISTENER_DETAIL_SETTINGS` + 서비스 ComponentName)을 먼저 요청한다.
     그 화면이 기기에 없으면 전체 목록, 그것도 없으면 앱 정보 화면을 연다.
   - **갤럭시(SM-N986N, Android 13 확인):** 상세 화면 요청을 받아도 One UI가 전체 목록을 보여준다. 목록에서 직접 찾아 켜야 한다 (한 번 스크롤).
   - 목록 강조 요청: `:settings:fragment_args_key`와 `:settings:show_fragment_args` 번들에 서비스 ComponentName을 넣는다. AOSP Settings가 목록 항목 키로 쓰는 값이다. 공개 API가 아니어서 지원하지 않는 기기는 무시한다.
     - **갤럭시(Android 13) 확인:** 목록이 MyCarHub 항목까지 자동 스크롤되고, 그 행이 잠깐 회색으로 강조된다 (시스템 기능).
   - 폰 빌드 전용 아이콘(노란 배경·자동차): 목록에서 기본 안드로이드 아이콘 앱들과 구분된다.
   - 설정 화면 위에 안내 띠 띄우기는 검토 후 넣지 않았다. 갤럭시는 이 화면이 열려 있는 동안 다른 앱의 오버레이를 강제로 숨긴다 (`mForceHideNonSystemOverlayWindow=true`, 탭재킹 방지). 다른 앱 위에 표시 권한이 있어도 마찬가지다.
   - 돌아오면 허용 여부를 자동으로 다시 확인한다. 허용되었으면 안내 메시지를 띄우고, 아니면 [다시 열기]·[앱 정보]·[닫기] 안내가 나온다.
   - 회색으로 막혀 있으면 [앱 정보] → 오른쪽 위 ⋮ → **제한된 설정 허용** 후 [다시 열기]. ADB로 설치한 경우에는 이 제한이 걸리지 않는다 (확인함). 브라우저·파일 앱으로 설치한 경우에 걸린다.
   - 다른 앱 위에 표시: 갤럭시는 목록이 열리지만 MyCarHub 위치로 스크롤된다. 알림 권한이 '다시 묻지 않음'이면 MyCarHub의 앱 알림 화면으로 바로 간다.
3. 음성비서에서 "최근 메시지 읽어줘", "카카오톡에 온 메시지 읽어줘"라고 말한다.
4. 읽은 뒤 "○○라고 답장해 줘"라고 말한다. 확인 질문에 "응" 또는 "보내"라고 답하거나 [보내기]를 누르면 전송된다.
5. 알림 접근 해제는 같은 설정 화면에서 한다.

자세한 설계와 미검증 항목은 [VOICE_ASSISTANT.md](VOICE_ASSISTANT.md)의 '메시지 읽기·답장'을 참고한다.

## 지원하지 않거나 검증할 수 없는 것

- **메시지 읽기·답장의 차량 동작:** 차량용(car) 빌드는 이 기능을 지원하지 않는다 (AAOS 정책).

- **주행 제한:** 폰에는 주행 상태가 없어서 주행 중 차단은 동작하지 않는다. 화면 띠에 "검증 아님"으로 표시된다. 주행 제한은 차량(car 빌드)에서 검증해야 한다.
- **Pleos 차량 기능·Gleo와의 마이크 경합:** 폰에서는 확인할 수 없다.
- **측정 데이터 가져오기:** `tools/pull_measurements.ps1`은 차량 에뮬레이터(user 10, `com.mycarhub`) 전용이라 phone 빌드(`com.mycarhub.phone`)에는 쓸 수 없다.

## 빌드

```powershell
cd F:\MyCarHub
.\gradlew.bat --offline :app:assemblePhoneDebug
# 결과: F:\MyCarHub\app\build\outputs\apk\phone\debug\app-phone-debug.apk
```

## USB 디버깅 설치

1. 폰에서 개발자 옵션을 켠다: 설정 → 휴대전화 정보 → 소프트웨어 정보 → '빌드번호'를 7번 누른다.
2. 설정 → 개발자 옵션 → **USB 디버깅**을 켠다.
3. USB로 PC에 연결하고, 폰에 뜨는 'USB 디버깅 허용' 창에서 PC를 허용한다.
4. PC에서 실행한다:
   ```powershell
   & 'C:\Android\Sdk\platform-tools\adb.exe' devices          # 폰 시리얼 확인 (unauthorized면 3번 다시)
   & 'C:\Android\Sdk\platform-tools\adb.exe' -s <폰시리얼> install -r 'F:\MyCarHub\app\build\outputs\apk\phone\debug\app-phone-debug.apk'
   ```
   차량 에뮬레이터가 켜져 있으면 기기가 2대로 잡히므로 `-s <폰시리얼>`이 필요하다.
5. 폰 앱 목록에서 **MyCarHub 폰테스트**를 실행한다. 앱 이름이 다르고 패키지도 `com.mycarhub.phone`으로 별도라 차량용과 섞이지 않는다.
6. 로그 확인: `adb -s <폰시리얼> logcat -s PhoneTest VoiceAssistant SpeechToText WakeWordManager`
7. 삭제: `adb -s <폰시리얼> uninstall com.mycarhub.phone`

## 백그라운드 호출 (플로팅, phone 빌드만)

다른 앱을 쓰는 중에도 등록한 호출어를 말하면 음성비서 창이 뜬다.

**켜기**

1. 메인 화면 맨 위 노란 띠의 **[백그라운드 호출 설정]**을 누른다.
2. 체크리스트 4가지를 갖춘다.
   - 호출어 등록
   - 마이크 권한
   - 알림 표시 권한 (Android 13+)
   - 다른 앱 위에 표시 (설정 화면에서 MyCarHub 폰테스트 켜기)
3. **[백그라운드 호출 켜기]**를 누른다.
   - 상태 표시줄에 마이크 사용 표시가 나오고, 알림창에 'MyCarHub 음성 호출' 알림이 생긴다.

**사용**

- 홈이나 다른 앱으로 가면 화면 왼쪽에 파란 MyCarHub 버튼이 뜬다. 회색이면 쉬는 중이고, 이유는 알림에 나온다.
- 호출어를 말하면 화면 위쪽에 음성비서 창이 뜨고 명령을 듣는다.
  - 처리가 끝나면 창이 닫히고 다시 호출어를 기다린다.
- 버튼을 누르면 수동 실행, 길게 누르면 듣기 중지, 끌면 이동한다.
- 알림의 [듣기 중지]와 [음성비서] 버튼으로도 같은 일을 할 수 있다.

**자동으로 쉬는 경우**

- MyCarHub 화면이 열려 있음: 그 화면이 직접 호출어를 듣는다.
- 화면이 꺼짐·잠금, 통화 중(전화·보이스톡 등).
- 다른 앱이 마이크를 쓰는 중: 무음이 들어오는 상태로 표시된다.
- 마이크를 열 수 없음: 10초 뒤 다시 시도한다.

**다시 켜기:** 휴대전화를 재부팅하거나 앱이 종료되면 백그라운드에서 다시 시작하지 않는다 (Android 정책). MyCarHub를 열면 다시 켜진다.

**접근성 서비스:** 필요하지 않아 사용하지 않는다.

### 채점 방식 비교 (검증 중, 판정 미적용)
- `EnrollmentMatchedScorer`(wakeword-phone): 실시간 구간을 등록과 같은 기준(소음+10 dB, 250 ms 끊김 합침, 경계 ±50 ms, 경계 ±30 ms 흔들기)으로 잘라 채점. 호출어보다 긴 덩어리는 기존 창 이동 방식.
- 폰 로그 `segment … score=(기존) matched=(등록 방식) threshold=…` 와 `calibration: … live LOO=[…] matched LOO=[…]`로 실제 목소리에서 두 방식을 비교한다. 판정은 기존 점수·기존 기준(0.202) 그대로.
- PC 비교: `gradlew --offline -q :wakeword-eval:run --args="compare"` (TTS '붕붕아'/'아이오닉', 같은 오인식률에서 감지율·AUC). TTS에서는 단독 호출 점수는 같거나 좋아졌지만 음높이·소음 변형 포함 전체로는 기존보다 낫지 않음 → 실기기 데이터로 판단.

## 양방향 음성 대화 (phone 빌드)
- 흐름: 호출어 또는 [직접 음성비서 실행] → "네, 말씀하세요!"(TTS) → 듣기 → 실행 → 결과를 음성으로 안내 → 필요하면 다시 듣기.
  - "카카오톡 열어줘" → "카카오톡 열게요." → 실행 (화면 닫힘)
  - "최근 메시지 읽어줘" → "최근 메시지를 읽어드릴게요. (내용) 답장할까요?" → "응"/"답장해 줘" → "뭐라고 답장할까요?" → 내용 → "…라고 보낼까요?" → "응"일 때만 알림 답장(RemoteInput)으로 전송 → 결과 안내
  - "아니/취소" 종료, "다시 말해줘" 마지막 말 반복, 대답 없음·인식 실패는 한 번 다시 묻고 두 번째면 종료 → 화면이 닫히고 호출어 대기
- 말하는 동안 인식기를 열지 않고, 말이 끝난 뒤 350 ms 쉬고 듣는다 (자기 목소리 재인식 방지).
- 코드: `app/src/phone/java/com/mycarhub/phone/conversation/` (PhoneConversation, PhoneSpeaker, PhoneAssistantActivity, VoiceSettingsActivity, AudioRoute). 차량용 VoiceAssistantSession·AssistantActivity는 그대로.
- 설정 › 음성 및 말하기: 기기 안 한국어 TTS 음성만 표시(성별은 엔진 음성 이름으로 알 수 있을 때만), 속도 0.5~2.0배(0.1 단위, 기본 1.0), 미리 듣기, 값은 `phone_voice_output` 설정에 저장.
- 자동차 블루투스: 음성 안내 출력은 시스템이 선택(A2DP 연결 시 차량 스피커). 음성 인식 입력은 휴대폰 마이크 (차량 마이크/SCO 미지원, 연결 여부만 표시).
- 로그 태그: `PhoneConversation`(단계·명령 종류·결과만, 인식 문장·메시지 내용은 남기지 않음), `PhoneSpeaker`(엔진·음성 목록).

## 비슷한 이름으로 메시지 찾기 (phone 빌드)

- 이름 비교: `assistant-phone` 모듈(폰 전용, 차량용 APK에 포함되지 않음)의 `KoreanNameMatcher` — 초성·중성·종성 발음 유사도. PC 검사: `gradlew --offline :assistant-phone:selfTest`
- 후보: 현재 알림에 있는 메시지의 보낸 사람·단체방 이름 + (설정에서 허용한 경우) 연락처 이름. 기기 안에서 요청 때만 읽고 저장·로그하지 않는다.
- 판정: 정확히 같음 → 바로 / 하나만 비슷함(0.75 이상, 2등과 0.1 이상 차이) → "OO 말씀하시는 거죠?" / 여럿 → "A, B 중에서 누구인가요?" / 낮음 → 다시 묻기(1회) 후 종료
- 메시지가 없는 사람은 "OO에게서 온 메시지 알림이 지금은 없어요"라고 말한다 (만들어 내지 않음). 답장은 받는 사람과 내용을 함께 확인한 뒤 '응'일 때만 보낸다.

실기기 확인 순서
1. "동지님 메시지 읽어줘" (동진님 알림이 있는 상태) → "동진님 말씀하시는 거죠?" → 응 → 동진님 메시지 읽기
2. "동진님한테 답장해줘" → "동진님에게 뭐라고 답장할까요?" → 내용 → "동진님에게 …, 라고 보낼까요?" → 응
3. 비슷한 이름이 여럿 있는 상태에서 → 후보 이름을 읽고 묻는지, "첫 번째"/이름으로 고르는지
4. 없는 이름("철수 메시지 읽어줘") → 다시 묻고, 두 번째에는 종료

이름 찾기 진단 (logcat `PhoneConversation`)
- 항상: `person match=… messages=… fromMessages=… contactsPermission=… contacts=…` (개수만)
- 개발 빌드만: `person debug heard=… words=… query=… candidates=…` (인식 문장·이름, 기기 logcat에만)
- 후보가 0개면 비슷한 이름을 찾지 않고 이유(메시지 알림 없음 / 연락처 권한 꺼짐)를 말한다.

## 상시 호출어 듣기 — 다른 앱 사용 중 호출 (phone 빌드)

- 호출어 감지는 `FloatingVoiceService`(포그라운드 서비스, type=microphone) 하나가 맡는다. 메인 화면의 [호출어 듣기 켜기]·설정의 [호출어 상시 듣기]가 이 서비스를 켜고 끈다.
- 흐름: 호출어 감지 → (메인 화면이면 대화 화면 / 다른 앱이면 그 위의 음성비서 창) → STT → 명령 실행 → TTS 대답 → 창 닫힘 → 0.5초 뒤 다시 감지. 대화 중에는 감지를 멈춘다(자기 목소리 재인식 방지).
- 앱 실행 뒤 MyCarHub로 돌아오지 않는다. 실행한 앱 위에서 계속 듣는다.
- 필요 조건: 호출어 등록, 마이크 권한. 다른 앱 사용 중 호출에는 '다른 앱 위에 표시'가 필요(창 표시 + 백그라운드 앱 실행 허용). 없으면 MyCarHub 화면에서만 듣는다. 알림 권한은 선택(알림창 [듣기 중지] 버튼 표시용).
- 쉬는 경우: 화면 꺼짐·잠금(잠금 해제하면 자동 재개), 통화 중, 메인 화면 외 MyCarHub 화면(대화·등록·설정), 다른 앱이 마이크 사용.
- 시스템이 앱을 종료하거나 재부팅하면 멈춘다. 백그라운드에서 마이크 서비스를 다시 시작하는 것은 Android 정책상 불가하므로 MyCarHub를 한 번 열면 다시 켜진다.
- 로그 태그: `FloatingVoice`(서비스 시작·중지), `WakeWordBackground`(감지 점수·감지).

실기기 확인 순서
1. 설정 › 상시 듣기 상태에서 '다른 앱 위에 표시' 허용 확인, 메인 화면 "● 상시 듣기 켜짐" 확인
2. "뿡뿡이" → "카카오톡 열어줘" → 카카오톡 실행, MyCarHub로 돌아오지 않음
3. 카카오톡 화면에서 "뿡뿡이" → 음성비서 창 → "유튜브 열어줘" → 유튜브 실행
4. 홈 화면에서도 호출되는지
5. 알림창 [듣기 중지] 또는 플로팅 버튼 길게 누르기 → 듣기 꺼짐
6. 화면을 껐다 켜고 잠금 해제 → 다시 듣는지
## 카카오톡 이름·권한 자동 요청·상시 듣기 초기 설정 (2026-11-08)

- 카카오톡 친구 목록: 다른 앱이 읽을 수 있는 공식 인터페이스가 없다 (연락처에 동기화되지 않음, Kakao SDK 친구 API는 카카오 서버·로그인 동의 필요, 같은 앱 사용자만). 대신:
  - 실제 알림의 보낸 사람·단체방 이름 (기존)
  - 설정 › 자주 연락하는 사람: 이름 직접 등록 또는 지금 알림에서 골라 추가 (이름만 기기 저장)
  - 등록 이름과 맞아도 메시지는 그 사람의 알림이 있을 때만 읽는다
- 권한 자동 요청 (PermissionGate / PermissionRequestActivity): 마이크·연락처는 권한 창, 알림 접근·다른 앱 위에 표시는 해당 설정 화면. 허용하면 원래 명령을 이어간다. 거부한 권한은 음성 대화에서 다시 자동으로 띄우지 않는다 (화면 버튼으로는 가능).
- 상시 듣기 초기 설정: 설정이 끝나지 않았으면 앱을 열 때 한 번 안내 화면 → [상시 듣기 시작]: 호출어 등록 → 마이크 → 알림 표시(선택) → 다른 앱 위에 표시 → 서비스 시작. 완료 후 다시 묻지 않음. 이미 다 갖춘 기존 사용자는 안내 없이 완료 처리.

확인할 것
1. 카카오톡 알림이 없는 상태에서 "동지님 메시지 읽어줘" → 등록 이름이 없으면 등록 안내, 연락처 권한이 없으면 권한 창 1회
2. 설정 › 자주 연락하는 사람에 '동진님' 등록 → "동지님 메시지 읽어줘" → "동진님 말씀하시는 거죠?" → 알림이 없으면 없다고 말함
3. 알림 접근을 끈 상태에서 "최근 메시지 읽어줘" → 설정 화면이 열림 → 허용 후 돌아오면 이어서 읽음
4. 권한 거부 후 같은 명령 → 다시 띄우지 않고 이유만 말함
